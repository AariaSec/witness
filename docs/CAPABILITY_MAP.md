# Capability and evidence map

One table, for a reviewer who wants the whole truth without
cross-referencing `README.md`, `docs/NUMBERS.md`, `docs/LIMITATIONS.md`,
and `docs/ARCHITECTURE.md` separately. This file doesn't introduce any
new claim — it's a reformatting of what those four already say, so if
this table and one of them ever disagree, the source doc is
authoritative and this file has drifted (file an issue against it).

## Maturity labels

- **Current** — implemented, with real executable evidence in this repo:
  a passing test, a frozen run, or a reproducible command.
- **Partial** — a real, bounded implementation exists, but doesn't cover
  everything the headline claim might imply.
- **Experimental** — implemented, but explicitly marked non-authoritative
  or advisory-only (never gates pass/fail, or is disclosed as small-n).
- **Directional** — a stated design intent, not yet built.
- **Held** — deliberately kept out of this public repo. The generated
  *artifacts* it produces (bundles, scores) are public and independently
  verifiable even when the *logic* that generated them is not.

## How to read a disagreement

If this table says something a source doc doesn't (or vice versa), the
source doc wins — `docs/NUMBERS.md` for every number and frozen `run_id`,
`docs/LIMITATIONS.md` for every disclosed gap, `docs/ARCHITECTURE.md` for
how a mechanism actually works. This file is a map, not the territory.
